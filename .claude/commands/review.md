# /review

スタッフエンジニアの視点で厳格なコードレビューを実施する。

## Goal

バグ、セキュリティ問題、設計の問題、パフォーマンスの問題を発見し、改善提案を出す。

## Suggested Sequence

1. `git diff main...HEAD` または指定されたPRの差分を取得する
2. 以下の観点でレビューする：
   - **正確性**: バグ、エッジケース、エラーハンドリング
   - **セキュリティ**: インジェクション、認証・認可、シークレット漏洩
   - **設計**: 単一責任、依存関係、過度な抽象化
   - **パフォーマンス**: N+1クエリ、不要な再レンダリング
   - **テスト**: テストカバレッジ、テストの品質
3. 重大度 (Critical / Major / Minor) で分類して出力する

## Notes

- 褒めることより問題を見つけることに集中する
- 「なぜそうするのか」の理由も説明する
